C@ Tooling and Ecosystem

1. Design Decisions

1.1 Primary tools
- paw build
- paw run
- paw test
- paw bench
- paw fmt
- paw lint
- paw doc
- paw add
- paw update
- paw audit
- claw check
- claw build
- claw emit-air
- claw emit-oir
- claw emit-lir
- claw emit-llvm

1.2 Formatter
- Canonical formatting is mandatory.
- One official formatter only.
- Formatter is syntax-preserving and stable across minor versions.

1.3 Linter
The linter checks:
- needless clone
- hidden allocation patterns in hot paths
- large owned pass-by-value at public boundaries
- ambiguous numeric literals
- realm visibility leaks
- raw block expansion
- defect-prone APIs
- style consistency

1.4 Documentation
- `paw doc` extracts shared items and type signatures.
- Documentation format includes ownership category and failure types.
- Examples compile as tests.

1.5 IDE protocol
- Language server provides:
  - diagnostics
  - jump to definition
  - find references
  - rename
  - hover type and ownership info
  - view-scope explanation
  - exhaustiveness hints

1.6 Package ecosystem policy
- Standard package registry with signed index metadata
- Reproducible lock files
- Security advisories integrated into `paw audit`
- Public packages must declare supported edition and minimum toolchain

1.7 Edition policy
- Editions group source-breaking language changes.
- Old editions remain supported with compatibility diagnostics for a defined window.
- Formatter output is edition-aware only when grammar requires it.

2. Rationale

FAST
- Strong tooling reduces engineering friction and shortens feedback loops.
- IR emission tools help performance tuning and compiler validation.

SAFE
- Audit, lint, and language server ownership insight reinforce safe usage.
- Signed registry metadata improves supply-chain trust.

SIMPLE
- One official toolchain entry point reduces ecosystem fragmentation.
- Formatter and linter settle style arguments automatically.

3. Constraints

- Tooling must reflect the exact language semantics, not approximate them.
- IDE ownership explanations must be derived from compiler truth.
- Registry policies must remain deterministic and automatable.
- Tool output must remain scriptable for CI.

4. Trade-offs

- Official tooling centralization reduces fragmentation but limits ecosystem variance.
- Mandatory formatting reduces stylistic freedom.
- Rich compiler tooling increases implementation scope, but is necessary for production adoption.
