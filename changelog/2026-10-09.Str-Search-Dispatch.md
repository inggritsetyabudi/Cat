# C@ Compiler — Changes Log (Generated 2026-10-09)

## Receiver-First `Str` Search Methods

### Gap yang Direproduksi
Fixture Cat yang memanggil `Str.starts_with`, `contains`, dan `ends_with` lolos `claw check`, tetapi `claw llvm` berhenti pada `LLVM lowering does not yet support builtin method 'Str.starts_with'`. Ketiga metode memang terdaftar di semantic analysis, namun belum mencapai backend/native.

### Implementasi
- LLVM lowering sekarang memetakan ketiga receiver-first method ke helper runtime native tanpa alokasi.
- Runtime membandingkan byte persis pada slice `Str`; prefix/suffix/needle kosong cocok, prefix/suffix yang lebih panjang dan substring yang tidak ditemukan tidak cocok.
- Dokumentasi builtin-methods sekarang membedakan inventory PRD, registrasi semantik, lowering LLVM, dan dukungan end-to-end.
- Audit mencatat perbedaan belum terselesaikan: PRD menyatakan `slice(range) -> Str`, sedangkan compiler menerima `slice(start, length) -> ref Str`. Tidak ada klaim bahwa kontrak PRD telah selesai.

### Regression Coverage dan Validasi
| Area | Bukti validasi |
|---|---|
| Frontend positif | Receiver-owned dan `ref Str`; prefix, suffix, substring; lebih panjang/tidak ditemukan; empty strings; exact multi-byte UTF-8 needle |
| Frontend negatif | Argumen bukan `ref Str` ditolak; receiver `Int32` tanpa method ditolak |
| Backend LLVM | Ketiga runtime call terlihat di IR; LLVM IR verifier lulus |
| Native | Cat fixture dibangun dan dijalankan; output `str-search-ok` |
| Suite/build | CMake/Ninja build dan seluruh frontend/backend/native suites lulus |

### Batas
Ini hanya vertical slice `Str` untuk `len`, `is_empty`, `starts_with`, `ends_with`, dan `contains`. Metode lain di katalog tidak diklaim selesai. Pencarian adalah byte-exact pada UTF-8, bukan Unicode normalization, case folding, atau grapheme matching. General lifetime inference tetap tidak berubah dan di luar cakupan.
