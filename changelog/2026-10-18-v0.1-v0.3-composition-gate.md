# Gerbang regresi kombinasi v0.1–v0.3

## Perubahan

Menambahkan matriks penerimaan tracked di `docs/v0.1-v0.3-acceptance-matrix.md`, dengan pemetaan perubahan dokumen (D) versus implementasi compiler (K), G1–G8, kriteria PRD per versi, fixture yang relevan, batas staged/unsupported, dan blocker yang masih terbuka. Ini pengerasan tes yang terpisah dari fix inline-call sebelumnya, disertai satu perbaikan konteks tipe implicit return yang memang sudah diwajibkan subset v0.2; bukan perubahan desain bahasa.

`claw/tests/integration/run_composition_tests.py` menjadi bagian wajib full suite. Empat program menggabungkan fungsi, nilai `if`/`pick`, choice, `Result`/`Maybe`/`try`, array dan indexed assignment, nested tuple pattern, range/scan integer dan Char, loop control, borrowed/owned string, implicit return, serta workspace/import. Cabang gagal dan cleanup owned String juga dieksekusi. LLVM hasil native build di-relink pada O0/O2 biasa dan O0/O2 dengan ASan/UBSan/LSan; stdout setiap target harus persis sama dengan ekspektasi. Total pada Linux: **20 eksekusi target**, bukan hanya penerimaan frontend.

## Defect compiler baru yang ditemukan dan diperbaiki

Pada baseline `80a4a20`, fungsi `-> Result[Int32, String]` dengan `val value = try read(flag)` diikuti implicit tail `Ok(value + 1)` ditolak sebagai `Undefined variable: Ok`; versi dengan `return Ok(...)` diterima. Ini bertentangan dengan implicit return yang didokumentasikan, bukan syntax staged. Sema sebelumnya hanya memberi expected return type pada tail `if`/`pick` dan tuple literal. Guard kini menambahkan implicit tail ber-return choice (Result/Maybe/custom). Jalur inferensi numerik biasa tetap seperti sebelumnya: percobaan guard terlalu luas tertangkap golden AIR dan tidak dipertahankan. Fixture `composition_implicit_result.cat` menjalankan check/LLVM/build/native hingga target O0/O2 dan sanitizer, mencakup sukses/gagal Result, Some/None, dan choice pengguna; stdout exact `42`, `missing`, `5`, `none`, `9` pada baris terpisah.

Matriks negatif menambahkan **13 fixture × empat command = 52 pemeriksaan**: `check`, OIR, LLVM, dan native build. Kontrak mencakup diagnostik lengkap, file/baris/kolom, exit bukan nol, stdout kosong, dan ketiadaan artefak LLVM/executable. Borrowed field pada shape normal dan owned tuple projection/partial move yang unsupported tetap ditolak; tidak dipromosikan menjadi fitur positif.

Oracle deterministik menambahkan **100 kasus** (seed `0xC0FFEE`): **44 accepted, 56 rejected**, termasuk **13 accepted dibangun/dijalankan native** dengan stdout exact. Matcher tag choice/struktur nested tuple independen dibatasi pada binding/wildcard dan varian yang didukung; bukan bukti seluruh grammar pattern atau seluruh kombinasi bahasa. Review menemukan bahwa wildcard berulang sempat dikecualikan terlalu luas pada oracle awal; guard diperketat dan empat kasus regresi ditambahkan. Ini defect test harness yang diperbaiki, bukan defect compiler baru.

CI menambahkan job Linux compiler host ASan/UBSan dengan leak detection aktif (`detect_leaks=1`); seluruh suite yang sama wajib dijalankan. Instrumentasi compiler dan relink target diuji terpisah. Runtime sanitizer target wajib di Linux; platform lain mencoba probe dan melaporkan SKIP hanya bila runtime tidak tersedia. Windows O0/O2 biasa tetap wajib.

## Bukti dan batas klaim

Bukti run final dicatat di matriks penerimaan dan PR #25, termasuk clean disposable Release/full suite, compiler sanitizer/full suite, review independen, serta CI Linux dan Windows MSYS2 UCRT64 pada head final. Hasil kandidat sebelumnya tidak menggantikan bukti head final.

**Gate menuju v0.4 belum lulus.** PR22 (owned-shape projection), PR23 (division/remainder edges), dan PR24 (target-direct float literal) tetap OPEN dan tidak disentuh. Audit D penuh/G2/G7 belum ditetapkan; doc-test menjalankan dua blok executable tetapi melewati 13 proposal dan dua text. Koleksi Vec/Set/Map, arbitrary owned aggregate, pattern penuh, dan slicing universal masih memiliki gap. Tidak menyatakan seluruh v0.1–v0.3 selesai atau bebas semua bug kode/memori.

Tidak ada merge, rebase, version bump, tag, release, perubahan Arena, implementasi v0.4, Float128, f-string, atau Show. Regresi versi bawah wajib terus dijalankan saat naik versi, sehingga tidak perlu mengulang audit dari nol tetapi tetap dapat menangkap regresi baru.
