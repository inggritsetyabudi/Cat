# v0.2 — Materialisasi literal Float32/Float64

Native backend sebelumnya menerima fungsi dengan parameter float, tetapi tidak dapat mematerialisasi literal float sebagai argumen atau nilai return. LLVM menolak nilai desimal mentah (dan nilai integer yang dikontekstualkan sebagai float) karena `ensureValue` hanya mengenali literal integer.

Backend kini mem-parsing literal dengan `std::from_chars` langsung ke tipe target (`float` atau `double`), lalu menuliskan konstanta LLVM hex berdasarkan bit hasil pembulatan tersebut. Untuk `Float32`, nilai binary32 dipromosikan tepat ke `double` sebelum encoding hex; LLVM kemudian mengonversinya kembali secara eksak ke `float`. Jalur ini juga menangani literal integer berkonteks float. Sema yang ada tetap menjadi penjaga overflow/underflow/non-finite sebelum codegen.

Regresi native memanggil fungsi negasi `Float64` dan `Float32`, membandingkan hasil runtime terhadap nilai negatif ekspektasi, serta menguji `negate64(0)`; program mencetak `1`. LLVM IR diperiksa untuk konstanta hex, `fneg double`, `fneg float`, dan perbandingan float.

Verifikasi akhir: clean build seluruh target dan `bash claw/tests/run_all_tests.sh` berhasil; fixture native benar-benar menjalankan kedua negasi dan mencetak `1`.

Follow-up terpisah memverifikasi signed zero lewat output `println` native: `negate64(0)`/`negate32(0)` tercetak `-0`, sedangkan zero positif tercetak `0`. Lihat `2026-10-11-v0.2-signed-zero-native-observation.md`; assertion ini terbatas pada formatter native yang dibundel, bukan jaminan format lintas-backend.
