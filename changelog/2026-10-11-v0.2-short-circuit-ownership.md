# v0.2 — Ownership pada short-circuit

Sebelumnya ownership checker selalu memproses RHS `and`/`or`, meski nilai literal di kiri membuat RHS pasti dilewati. `true or consume(anchor)` dapat kehilangan drop milik caller, sedangkan `false and consume(anchor)` dapat keliru menandai `anchor` sebagai moved.

Pemeriksaan kini menghormati short-circuit literal: RHS hanya mengubah state ownership jika memang dievaluasi. Regresi memastikan `anchor` tetap dapat digunakan, drop caller tetap ada di OIR, dan program native mencetak `held`. Untuk kondisi kiri dinamis, conditional move pada RHS sekarang menghasilkan diagnostic eksplisit; lowering belum memiliki representasi cleanup path-dependent yang aman. Gunakan `if` eksplisit untuk transfer ownership tersebut.

Tes: frontend suite (termasuk tes negatif conditional move), assertion drop OIR, serta build dan eksekusi fixture native short-circuit.

Verifikasi akhir: clean build seluruh target dan full test suite berhasil.
