# 2026-10-11 — Kontrak `try` dan satu lapis `Result` (v0.2)

## Temuan dari reproduksi

Compiler pada branch kerja menerima `val x = try f()`; menolak `var x = try f()`; menolak `return try f()` di parser dengan `Expected expression.`; menolak shorthand saat error type berbeda; dan menolak `else err { ... }` yang masih dapat jatuh lanjut. Untuk operand bertipe `Result[Result[T, E], E]`, `try` menghasilkan payload `Result[T, E]`—hanya tag `Result` terluar yang dibuka.

Validasi semantik inti sudah ada pada source branch: shorthand membandingkan error type dengan `sameType`, sedangkan blok `else` harus pasti terminal. Perubahan implementasi pada irisan ini membuat pesan larangan `var = try` final dan eksplisit; tidak menyiratkan bahwa dukungan `var` hanya ditunda.

## Perubahan dan regresi

Pesan `var x = try ...` kini menyatakan bahwa `try` hanya boleh menjadi initializer `val` dan menyarankan pola `val t = try ...` lalu `var x = t`. Bagian §5 PRD ditandai `[sudah]` setelah verifikasi.

| Lapisan | Regresi |
| --- | --- |
| Frontend/AIR | Kasus positif dan negatif untuk `var`, `return try`, mismatch error type shorthand, blok `else` nonterminal, serta tipe AIR pada `Result` bersarang. |
| OIR | Golden `claw/tests/oir/golden/try-contract.oir` memastikan tiap `TryStmt` membuka satu `Result`; kasus-kasus negatif juga diuji pada tahap OIR. |
| Backend LLVM | Assertion memastikan fungsi `unwrap_one` hanya menguji satu tag untuk `Result` terluar. |
| Native | Jalur sukses dan gagal diuji untuk shorthand dan `else` lokal, serta payload `Result` bertingkat. Output yang diharapkan: `37`, `step-failed`, `-1`, `37`, `step-failed`, `41`. |

## Verifikasi

Clean CMake configure/build dari nol berhasil dengan Ninja dan GCC 13.3.0. `bash claw/tests/run_all_tests.sh` lulus seluruh doc-test, frontend, OIR, backend LLVM, dan native suite pada salinan disposable, termasuk compile serta eksekusi fixture native baru. Working tree utama dan semua perubahan lokal yang sudah ada dipertahankan; runner yang menulis artefak hanya berjalan di salinan disposable.

## Catatan follow-up dan status historis

Pernyataan di atas bahwa §5 ditandai `[sudah]` adalah catatan yang benar untuk validasi awal pada saat changelog ini dibuat. Review/reproduksi lanjutan kemudian menemukan dua blocker: ownership `try` pada `Result` owned (UAF/double-free) dan perbandingan nominal generic saat imported item memakai alias. Karena itu status di PRD diturunkan kembali menjadi `[parsial]`; keputusan desain §5 tidak berubah.

Follow-up ownership dan native sanitizer dicatat terpisah di [`2026-10-11-v0.2-try-owned-result-transfer.md`](./2026-10-11-v0.2-try-owned-result-transfer.md), sedangkan identitas imported alias dicatat di [`2026-10-11-v0.2-try-import-alias-type-identity.md`](./2026-10-11-v0.2-try-import-alias-type-identity.md). Perbaikan dan regresi terarah kini lulus, termasuk alias positif, generic/cross-module mismatch negatif, OIR, dan native ASan/LSan; clean build dan suite penuh disposable terbaru juga lulus. Fresh independent review atas snapshot terkini memberi verdict `READY`. §5 tetap `[parsial]` sambil menunggu acceptance gate yang relevan dicatat, sehingga catatan ini tidak mengklaim status selesai saat ini.

## Batas yang tetap berlaku

`return try` bukan bentuk sumber yang didukung—parser menolaknya karena kontrak hanya memperbolehkan `try` pada initializer `val`. Grammar sumber `defect` belum diputuskan, sehingga tidak ada syntax `defect` baru. Arena tidak diubah oleh irisan ini.
