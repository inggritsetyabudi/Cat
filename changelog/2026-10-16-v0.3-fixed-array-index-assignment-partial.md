# 2026-10-16 — Fixed Array: indexed assignment parsial

## Masalah dan baseline

Pada baseline `origin/main` `b756b987a67c7ea449d76f9eedc4e2f6ce9a60a9`, program Cat nyata dengan `var values: Array[Int32, N]` maupun `var values: Array[UInt8, N]` menolak `values[i] = value` dengan diagnostik read-only `Fixed Array element assignment is out of scope`. OIR telah memiliki `StoreIndex`, dan backend LLVM telah menyediakan bounds-checked address/store path, tetapi kedua jalur itu perlu divalidasi sebagai satu rangkaian sebelum semantik assignment dibuka.

## Perubahan

- Mengizinkan hanya plain `=` ke elemen `Array[Int32, N]` atau `Array[UInt8, N]` melalui identifier binding lokal mutable `var`.
- Mempertahankan syarat index `USize`, kecocokan tipe elemen, dan pemeriksaan rentang literal `UInt8`.
- Mempertahankan penolakan untuk `val`, parameter, global, nested/unsupported/zero-length Array, serta assignment compound seperti `+=`.
- Menggunakan urutan StoreIndex yang ada: receiver/index dievaluasi sekali sebelum RHS. Pada LLVM, bounds guard dan jalur trap mendahului GEP dan store untuk `[N x i32]` maupun `[N x i8]`.
- Menambah frontend negatif/positif, OIR golden, backend guard-order assertions, native mutation/readback dan dynamic OOB trap, serta sanitizer coverage.

## Validasi

- Compiler berhasil dibangun dengan CMake pada worktree fitur dan pada salinan disposable clean.
- Focused frontend, OIR, backend, dan native suites lulus; native sanitizer ASan/UBSan/LSan lulus.
- Review independen read-only final: tidak menemukan blocker.
- Full `bash claw/tests/run_all_tests.sh` lulus pada salinan disposable setelah clean CMake build; suite docs, frontend, OIR, backend, native, dan CLI seluruhnya lulus.

Perubahan ini hanya membuka slice assignment elemen fixed Array yang sempit; PRD/roadmap tidak diubah dan tidak ada klaim penyelesaian `[sudah]`.
