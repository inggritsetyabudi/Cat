# PRD Ringkas generation (2026-10-18)

**Status:** documentation/tooling change at main baseline `e7789c6`; no compiler or language-design change.

## Changes

Added 22 human-authored `Ringkas: <text>` source markers to [PRD.md](../cat-northstar/PRD.md), one for every level-two heading outside code fences: §0, the decision-summary table section, and §1–§20. The original PRD text and newline bytes are otherwise preserved; nested headings do not require separate markers.

Added the deterministic Python-standard-library [generator](../tools/generate_prd_summary.py) and committed [PRD-RINGKAS.md](../cat-northstar/PRD-RINGKAS.md). Only source headings and authored marker payloads supply section content. The fixed header identifies provenance; no summaries are inferred from other paragraphs or legacy documents. Generation rebuilds the complete output without stale appended text. UTF-8 decoding is strict, source bytes are never rewritten, and output is UTF-8 without BOM, LF, with exactly one final newline on all platforms. No Unicode normalization, mojibake repair, or language-decision correction is performed.

The [Northstar index](../cat-northstar/README.md#ringkasan-otomatis-g7) documents scope, format, commands, reversible tooling defaults, and the generated-file policy. Regenerate with `python3 tools/generate_prd_summary.py`, commit source and output together, and use `--check` for read-only byte-exact validation.

## Validation

[Generator regressions](../claw/tests/docs/test_prd_summary.py) cover exact output, missing/duplicate/malformed/out-of-scope markers, new unmarked sections, nested headings, fenced pseudo-markers/headings, invalid UTF-8, Unicode preservation, LF/CRLF handling, idempotence, read-only checks, stale removal, source preservation, and invalid-source failure without output overwrite. They also strictly decode all six existing Northstar source/archive documents and compare the committed compact file with regenerated bytes.

The [doc-test entry point](../claw/tests/docs/run_doc_tests.sh) runs `--check` and these regressions before checking executable PRD examples. Both Linux and Windows UCRT64 CI already invoke that entry point through the complete suite, so generated drift is a CI failure rather than a silent regeneration. A deliberate stale-output probe confirmed that the actual doc-test entry point fails without rewriting the output.
