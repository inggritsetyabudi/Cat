# 2026-10-11 — Konsumsi owned `Result` pada `try` (v0.2)

## Masalah yang direproduksi

`try` sebelumnya menganalisis operand tanpa konsumsi ownership. Binding `Result` owned masih dianggap hidup setelah payload diambil; penggunaan ulang kemudian menghasilkan use-after-free/double-free pada native. Native regression juga mengungkap bahwa payload owned yang dipindahkan ke konstruktor `Ok(...)` atau `Fail(...)` masih dijadwalkan untuk drop lokal.

## Perubahan dan regresi

Ownership pass kini mengonsumsi operand `try`. Reuse binding setelahnya ditolak sebagai moved value. Argumen owned pada konstruktor varian dikenali sebagai transfer ownership, sehingga `return Ok(payload)`/`return Fail(err)` tidak membebaskan payload sebelum return.

| Lapisan | Bukti |
| --- | --- |
| Frontend/check | `revise_bad_try_owned_reuse.cat` wajib ditolak dengan `Use of moved value -> result`. |
| OIR | `try-owned-result.oir` memastikan tidak ada drop untuk source `result` yang telah dikonsumsi dan tidak ada drop payload sebelum transfer melalui `Ok`/`Fail`; temporary dan payload lokal yang memang tetap dimiliki scope tetap didrop. |
| Native | `revise_try_owned_result.cat` menjalankan jalur sukses/gagal untuk named dan temporary `Result`, termasuk return payload lewat `Ok`. |
| ASan/LSan | Fixture native dijalankan dengan `ASAN_OPTIONS=detect_leaks=1:halt_on_error=1`; kedua jalur lulus tanpa UAF, double-free, atau leak. |

## Verifikasi dan batas

Clean configure/build dan seluruh doc-test, frontend, OIR, backend LLVM, serta native suite lulus pada salinan disposable. Working tree utama tidak berubah oleh runner. Perintah `air` saat ini tidak menjalankan ownership pass; invalid reuse ditegaskan pada `check` dan OIR, bukan diberi ekspektasi palsu pada AIR. Tidak ada syntax `defect` yang ditambahkan dan Arena tidak disentuh.
