# Fixed Array UInt8 — partial slice

**Status:** implementation slice only. PRD §2 and its milestone remain partial and are not marked complete.

## Scope

This slice extends the existing fixed Array implementation from `Array[Int32, N]` to exactly two supported element types: `Array[Int32, N]` and `Array[UInt8, N]`. It does not claim support for every Array element type or completion of PRD §2.

`Array[UInt8, N]` supports typed construction and inference from UInt8-suffixed values, contextual typing of unsuffixed integer literals, read indexing with `USize`, and ordinary/indexed scans. Integer literals are validated against UInt8's `0..255` range. Mixed element types, wrong literal lengths, out-of-range values, and overflowing length literals are rejected. Other element types—including UInt16—remain unsupported.

The existing fixed storage and value ABI are preserved with element-aware layout: UInt8 arrays lower to `[N x i8]`, size `N` bytes and alignment 1. Aggregate argument/return classification uses that layout; a sufficiently large `Array[UInt8, 17]` exercises indirect return and parameter passing. Index expressions are evaluated once; a `USize` bounds guard dominates each `getelementptr inbounds` and load. Array scans use a `USize` index starting at zero and guard each read. UInt8 output uses the existing unsigned runtime printer.

## Explicit exclusions

No other element types, nested arrays, global arrays, mutable element assignment, or zero-length arrays were added. The PRD, milestone completion state, Range, Str, and Arena behavior were not changed.

## Baseline evidence

A clean compiler built from the pre-change revision rejected a Cat source that annotated and constructed `Array[UInt8, N]`, indexed it, and scanned it: the element type was explicitly unsupported, and indexed scans were limited to Range or `Array[Int32, N]`. The change removes only those blockers for UInt8; indexing and scan safety constraints remain.

## Tests

Focused frontend, OIR, LLVM backend, and native suites pass. The native suite includes the UInt8 out-of-bounds trap case and ASan/UBSan/LSan execution. Frontend negatives cover unsupported UInt16, mixed element types, literal overflow, length mismatch/overflow, zero length, nested/global arrays, and mutable element assignment. After a clean CMake configure/build, the full `bash claw/tests/run_all_tests.sh` also passed in a disposable copy of this worktree.
