# 2026-10-11 — Identitas tipe nominal melalui import alias (v0.2)

## Masalah yang direproduksi

Shorthand `try` menolak error type nominal generic yang sama jika caller memakai item alias: `Problem[Str]` dari signature modul dibandingkan sebagai nama berbeda dari `LocalProblem[Str]`. Identitas yang hanya memakai nama module yang terlihat juga berisiko menyatukan dua file dengan basename sama.

## Perubahan dan regresi

`ResolvedType` kini membawa identitas nominal berbasis path source ternormalisasi. Metadata identitas dipertahankan pada exported type dan saat item diimpor dengan alias. `sameType` membandingkan identitas nominal jika tersedia dan tetap membandingkan seluruh generic parameter secara rekursif, sehingga alias ke tipe yang sama diterima tanpa menyamakan instansiasi berbeda atau tipe bernama sama dari dua file/module berbeda.

| Kasus | Hasil |
| --- | --- |
| `Problem[Str]` dibanding `LocalProblem[Str]` dari item alias yang sudah didukung | Positif: `check`, AIR, dan OIR lulus. |
| `Problem[Str]` dibanding `LocalProblem[Int32]` | Negatif: shorthand error-type mismatch tetap ditolak pada check, AIR, dan OIR. |
| `Problem[Str]` dari dua file berbeda yang sama-sama bernama `problems.cat` | Negatif: identitas nominal berbeda tetap ditolak pada check, AIR, dan OIR. |
| Bentuk import/alias | Tidak ada grammar atau sintaks import baru; hanya bentuk item alias yang sudah digunakan suite. |

## Verifikasi

Clean configure/build dan seluruh doc-test, frontend, OIR, backend LLVM, serta native suite lulus pada salinan disposable setelah regresi path identity ditambahkan. Tidak ada file Arena yang diubah.
