# Top-level documentation comments and `claw doc` — v0.4 slice

**Status:** bounded implementation slice only. PRD §12 and the wider v0.4 milestone remain incomplete; this does not bump a version or create a release.

## Implemented

Top-level `///` comments are retained as declaration documentation. The parser strips the three-slash prefix and at most one following ASCII space, joins documentation lines with LF, and attaches the accumulated text only to the next top-level declaration. Blank lines and ordinary `//` or `/* ... */` comments do not break attachment. Documentation and its source span are stored on the AST declaration.

A non-fatal `doc` warning is emitted when documentation attaches to a non-`share` declaration, and an orphan-doc warning is emitted at EOF when no declaration follows. Warnings are surfaced by ordinary compiler commands as well as `claw doc`.

`claw doc <source.cat>` parses only the named source file and writes deterministic UTF-8 Markdown to stdout in declaration order. It emits a heading and documentation text for documented shared functions, shapes, and choices; undocumented shared items are omitted. It does not traverse imports or render fields/members.

## Baseline

At `origin/main` commit `b756b987a67c7ea449d76f9eedc4e2f6ce9a60a9`, a clean Linux CMake build succeeded. Before the change, `claw doc /tmp/claw-doc-baseline-input.cat` exited 1 with `Unknown command: doc`. A baseline `claw check` accepted `///` as an ordinary comment, consistent with the lexer discarding all `//` lines.
