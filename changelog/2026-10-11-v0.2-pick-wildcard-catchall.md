# 2026-10-11 — Catch-all `_` pada `pick`

## Perbaikan

Parser yang ada telah menerima `_` sebagai tag pattern; semantik kini mengenalinya sebagai catch-all, bukan varian choice bernama `_`. Catch-all menutup semua varian yang belum dicocokkan dan harus menjadi branch terakhir. Branch berikutnya ditolak dengan diagnostik unreachable. Dukungan berlaku untuk `PickExpr` dan `PickStmt`, dan wildcard tidak dimasukkan sebagai binding payload.

LIR/LLVM memperlakukan target `_` sebagai default switch target serta tidak menghasilkan defect fallback untuk nilai valid yang tidak tercantum eksplisit.

## Verifikasi

- Positif: frontend, OIR, backend, dan native mencakup wildcard expression serta statement; native memilih `606` dari branch eksplisit, `0` dari wildcard expression, dan `-1` dari wildcard statement.
- Negatif: frontend dan OIR memastikan wildcard non-final ditolak dan branch sesudahnya dilaporkan unreachable.
- OIR golden menampilkan branch `case _`; LLVM default label menuju block wildcard.
- Clean build serta full suite lulus pada salinan disposable.
